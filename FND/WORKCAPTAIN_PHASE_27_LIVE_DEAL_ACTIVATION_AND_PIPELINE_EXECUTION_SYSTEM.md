# WORKCAPTAIN / PROWORK — PHASE 27 LIVE DEAL ACTIVATION + PIPELINE EXECUTION SYSTEM

Version: 1.0
Status: ACTIVE
Phase: 27
Applies From Commit: 0b73a9fe7716aeec8dd6acf63f3da631236f563b

## 1. Purpose

This phase converts the presentation-converted and diligence-ready platform state into a governed live deal activation and pipeline execution system.

The objective is to create an operating layer for:

- board and investor opportunity progression
- enterprise pipeline activation
- sovereign and strategic partner pursuit
- evidence-backed deal stage control
- bounded external engagement execution

## 2. Outcomes

Phase 27 must establish:

- live deal activation framework
- pipeline stage model
- governed deal qualification protocol
- stakeholder pursuit playbooks
- live diligence execution workflow
- deal evidence and traceability model
- decision and escalation model
- bounded external claims discipline during pursuit

## 3. Preconditions

Phase 27 may proceed only if all of the following are true:

- source-of-truth commit matches approved baseline
- Phase 26 status is ready
- Phase 25 readiness artifacts exist
- Phase 24 certification artifacts exist
- external assurance boundary exists
- traceability model exists for presentation materials

## 4. Operating Boundary

Phase 27 authorizes live deal and pipeline operations only within the already certified and bounded assurance posture.

Phase 27 does not authorize:

- unsupported commercial promises
- regulator approval claims
- legal opinion claims
- third-party certification claims unless separately obtained
- any pursuit statement not mapped to approved artifacts

## 6. Pipeline Stage Model

The live pipeline must use explicit stages:

- identified
- qualified
- activated
- diligence
- proposal
- negotiation
- decision
- won
- lost
- parked

No opportunity may move silently between stages.

## 7. Deal Governance Rules

All live deals must be:

- artifact-backed
- stage-traceable
- owner-assigned
- boundary-controlled
- escalation-aware
- evidence-recorded

## 8. Pursuit Categories

Phase 27 must support three pursuit motions:

- investor pursuit
- enterprise pilot pursuit
- sovereign / strategic partner pursuit

Each must have its own playbook while remaining aligned to one common governance model.

## 9. Fail-Closed Rules

Phase 27 must block if any of the following occurs:

- baseline commit mismatch
- missing Phase 24 or Phase 25 or Phase 26 prerequisite artifact
- missing required Phase 27 artifact
- dirty working tree before finalization
- unsupported external claim introduced
- push failure

## 11. Non-Negotiable Rule

Every live deal and pipeline action must remain bounded by approved assurance artifacts and must be traceable to evidence and stage movement.
