# ROLE-BASED INTERFACE MODEL

## Purpose

This document defines the role-based interface model for WorkCaptain / ProWork.

## Role Principle

Each interface role must see only what is necessary for valid action, valid oversight, or valid assurance.

Visibility and actionability must remain bounded by:

- authority scope
- classification scope
- escalation relevance
- doctrine compatibility
- disclosure compatibility

## Core Roles

### 1. Executive role
Needs portfolio command, capital allocation, intervention, and strategic synchronization visibility.

### 2. Board role
Needs governance, assurance, certification, escalation, and institutional closure visibility.

### 3. Operator role
Needs workflow execution, intake processing, task progression, and escalation handling visibility.

### 4. Investor assurance role
Needs bounded assurance, disclosure, readiness, and confidence-safe visibility.

### 5. Partner / sovereign engagement role
Needs qualified engagement, controlled interaction, and classification-safe visibility.

### 6. Entity lead role
Needs local execution, local accountability, local escalation, and federated alignment visibility.

## Role Outputs

Each role definition must produce:

- role name
- permitted surfaces
- restricted surfaces
- allowed decisions
- escalation authority
- invalidity boundaries

## Role Rule

No role may gain de facto authority through interface visibility that exceeds its governed institutional authority.

## Outcome

The role-based model turns the institutional stack into bounded multi-role execution surfaces.
